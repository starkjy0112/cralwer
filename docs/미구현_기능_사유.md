# 미구현 기능 사유

## 1. 게시판 링크 추가 기능

### 요청사항
사용자가 대시보드에서 새로운 게시판 URL을 추가하면 자동으로 크롤링되는 기능

### 미구현 사유
현재 337개 크롤러는 각 사이트의 HTML 구조에 맞춰 개별적으로 제작되었습니다.
새 게시판을 자동으로 크롤링하려면 범용 크롤러가 필요하지만, 아래 이유로 현실적으로 어렵습니다.

**사이트마다 HTML 구조가 전부 다름:**
- 테이블 기반 (table > tbody > tr > td)
- 리스트 기반 (ul > li > a)
- div 기반 (div.list_item)
- iframe 기반 (eminwon, contract.seoul.go.kr)
- JSON API 기반 (AJAX 호출)

**검색 파라미터가 사이트마다 다름:**
- searchCnd / searchKrwd (eGovFrame)
- searchType / searchTxt (saeolGosi)
- stype / sstring (PCMS)
- q_searchKey / q_searchVal (Openworks)
- keyword / allKeyWord (커스텀)
- not_ancmt_sj (eminwon)
- 등 20가지 이상의 파라미터 조합

**페이지네이션 방식이 다름:**
- pageIndex, page, nPage, startPage, cpage, GotoPage, q_currPage 등
- GET / POST 방식 차이
- CSRF 토큰 필요 여부

**인코딩 차이:**
- UTF-8, EUC-KR
- curl subprocess 필요한 사이트 (hanayo.net)

### 향후 가능한 방안
- AI 기반 HTML 자동 파싱 (LLM으로 테이블 구조 자동 인식)
- 사용자가 CSS selector를 직접 지정하는 고급 모드
- 자주 사용되는 CMS 패턴(eGovFrame, saeolGosi, PCMS 등)을 자동 감지하는 반자동 방식


## 2. 지정게시판 연결 안 될 경우 통합검색으로 연결

### 요청사항
크롤러가 지정된 게시판에 접속 실패 시, 해당 기관의 통합검색 페이지로 자동 전환하여 검색

### 미구현 사유

**기관별 통합검색 URL을 매핑할 수 없음:**
- 337개 기관 중 통합검색 페이지가 있는 곳도 있고 없는 곳도 있음
- 통합검색 URL 형식이 기관마다 다름
  - 예: 여수시 → /total_search/total_search.html
  - 예: 양구군 → /md_allsearch/all_search_list
  - 예: 일부 기관은 통합검색 자체가 없음

**통합검색 페이지의 구조도 다름:**
- 일반 게시판과 HTML 구조가 완전히 다름
- 검색 결과 포맷 (카테고리별 분류, 건수 표시 등)이 제각각
- 새로운 파서를 기관별로 추가 작성해야 함

**사이트 장애 vs 크롤러 오류 구분 어려움:**
- 서버 타임아웃이 일시적인지 영구적인지 판단 불가
- 폴백으로 통합검색에 갔다가 원래 게시판이 복구되면 중복 데이터 발생

### 현재 대안
- 크롤러 에러 발생 시 **에러 상세 표시** (크롤러명 + 원인 + 사이트 직접 확인 링크) 구현 완료
- 사용자가 링크를 클릭하여 직접 사이트에서 확인 가능
