# 크롤러 검증 절차

## 개요

엑셀 1~373번 전체 사이트에 대해 337개 크롤러를 제작하고, 각 크롤러의 정상 작동 여부를 아래 절차로 검증했다.


## 1. 검증 방법: 건수 대조

크롤러가 반환하는 검색 결과 건수를 **실제 사이트에 직접 접속하여 검색한 건수**와 비교한다.

### 절차

1. 크롤러에서 `search("공고", max_pages=1)` 실행 → 총건수 확인
2. 크롤러에서 `search("용역", max_pages=1)` 실행 → 총건수 확인
3. 실제 사이트 URL에 접속하여 "공고" 검색 → 건수 확인
4. 실제 사이트 URL에 접속하여 "용역" 검색 → 건수 확인
5. 크롤러 건수와 사이트 건수 비교

### 판정 기준

| 결과 | 판정 | 조치 |
|------|------|------|
| 공고/용역 건수가 사이트와 일치 (±5건 이내) | ✅ 정상 | 없음 |
| 공고와 용역 건수가 동일 | ❌ 검색 미작동 | 검색 파라미터 수정 |
| 크롤러가 0건 반환 | ❌ 파싱 실패 | HTML 구조/파라미터 재분석 |
| 건수가 크게 다름 | ⚠️ 건수 차이 | 총건수 파싱 로직 수정 |

> **"공고"와 "용역" 두 키워드의 건수가 다르면 검색이 작동하는 것**이 핵심 판단 기준이다. 같으면 서버가 검색어를 무시하고 전체 목록을 반환하고 있다는 의미.


## 2. 검증 과정에서 발견된 주요 문제 유형

### 2-1. 검색 파라미터명 불일치
- 사이트 form의 실제 파라미터명과 크롤러가 보내는 파라미터명이 다른 경우
- 예: `srchKwd` → `srchKeyword` (경산/경주)
- 예: `searchType=tit` → `searchType=not_ancmt_sj` (구미/봉화/영천)
- 예: `searchCnd=SJ` → `searchCnd=0` (광진)
- 예: `searchType=DATA_TITLE` → `searchType=dataTitle` (전주)
- 예: `searchType=subject` → `searchType=SUBJECT`, `keyword` → `searchValue` (고령)

### 2-2. 총건수 파싱 오류
- 페이지네이션의 "전체 페이지 N"에서 계산한 총건수가 검색 결과가 아닌 전체 게시물 수를 반환
- 해결: 키워드 검색 시 첫 번째 항목의 번호(첫번호)를 총건수로 사용
- 적용 크롤러: 구미, 봉화, 영천, 청도, 칠곡, 포항, 문경 등 saeolGosi 패턴

### 2-3. HTTP 메서드 불일치
- 사이트가 POST를 요구하는데 GET으로 요청하거나, 그 반대
- 예: 서대문 — POST form submit 필요하나 서버가 검색어를 무시 → 클라이언트 필터링으로 전환

### 2-4. 서버가 검색을 지원하지 않는 경우
- POST/GET 모두 시도해도 검색어가 적용되지 않는 사이트
- 해결: 전체 데이터를 수집한 후 제목에 키워드 포함 여부로 클라이언트 필터링
- 적용 크롤러: 서대문 등

### 2-5. iframe 기반 사이트
- 구청 사이트가 외부 시스템(contract.seoul.go.kr)을 iframe으로 임베드
- 크롤러가 구청 사이트 HTML을 파싱하면 데이터가 없음
- 해결: iframe의 실제 src URL을 추출하여 직접 요청
- 적용 크롤러: 관악/금천/동대문 입찰


## 3. 크롤러 제작 체크리스트

새 크롤러 제작 시 아래 8단계를 순서대로 적용:

1. **크롤러 파일 생성** — URL fetch 후 HTML 분석, `search(keyword, max_pages)` 구현
2. **WORKERS = 20** 설정 — 멀티스레드 페이지 수집
3. **PAGE_SIZE 확인** — 서버가 페이지 크기 파라미터를 받으면 PAGE_SIZE=100
4. **키워드 검색 검증** — "공고"와 "용역" 검색 시 건수가 달라야 함
5. **서버사이드 날짜 필터 확인** — form에 날짜 input이 있으면 start_date/end_date 지원
6. **app.py에 import + CRAWLERS dict 등록**
7. **app.py DATE_SUPPORTED에 추가** — 날짜 필터 지원 크롤러만
8. **실제 사이트와 건수 대조 검증** — 위 1번 절차 수행


## 4. 최적화 적용 사항

| 항목 | 설정 | 비고 |
|------|------|------|
| WORKERS | 20 | 멀티스레드 페이지 수집 |
| PAGE_SIZE | 100 | 서버가 지원하는 경우 |
| HTML 파서 | lxml | 속도 최적화 |
| HTTP 어댑터 | HTTPAdapter(max_retries=3) | 재시도 로직 |
| 캐시 TTL | 30분 | 동일 검색 결과 캐싱 |
| 백그라운드 프리패치 | 적용 | 캐시 만료 전 갱신 |
